# 训练方法评估：现在的路子是不是最好？有没有更好的？

> 2026-09-15，基于三组公开资料 + 本机实测。
> 机器：RTX 4060 Laptop **8GB**（显存常年顶格、共享溢出 6~9GB）
> SFT＝指令微调，CPT＝继续预训练。

---

## 一、直接回答三个问题

### Q1：现在的微调方法（7B QLoRA）是最好的吗？

**在"7B"和"8GB"这两个前提下，它是被迫的选择，不是最优选择。**

2026 年的方法论共识（多份资料一致）：

| 方法 | 训练参数量 | 7B 显存 | 质量 | 适用 |
|---|---|---|---|---|
| 全参微调 | 100% | **60~100+ GB** | 最高 | 极端领域迁移、继续预训练 |
| LoRA | 0.1\~1% | 14\~16 GB | 接近全参 | 默认选择 |
| **QLoRA（本项目）** | 0.1\~1% | **6\~8 GB** | 略低于 LoRA | 消费级显卡 |

> 原话："**Under 8 GB VRAM → QLoRA. Nothing else fits.**"

所以不是"选得好"，是"没得选"。**但有三个没试过的改进空间**（见第三节）。

### Q2：在这台机器上，有没有更好的？

有，而且不止一条：

1. **换成更小的基座 + 16-bit LoRA**（见第三节 A）
2. **加一个"继续预训练"阶段**（见第三节 B）—— 这条最重要
3. **换 LoRA 变体 / 换训练框架**（见第三节 C）

### Q3：有没有"直接训练"而不是微调的方法？

分三种，可行性差别很大：

| 路线 | 在这台机器上 | 说明 |
|---|---|---|
| **从零训练** | ❌ **不可行** | 训练一个能写小说的模型要几百亿 token、几万 GPU 小时。本机算力差 3\~4 个数量级 |
| **继续预训练（CPT）** | ✅ **可行**（本机 1 epoch 约 15\~30 小时） | 用原始文本做 next-token 预测，**更新全部权重**。这才是"直接训练"在个人机器上的可行形态 |
| **全参微调（Full FT）** | ⚠️ 只能到 **≤1.5B** | 7B 要 60\~100GB，本机差 8\~12 倍；1.5B 配 8-bit 优化器勉强能挤进 8GB |

**结论：想要"直接训练"，唯一现实的路是 CPT（继续预训练）；若还想"更新全部权重"而不是适配器，就只能把基座换到 1.5B。**

## 二、🔴 最关键的一条发现：**"学文风"这件事，SFT 本来就不是对口的工具**

两份资料把这件事说得非常直白：

**Chris McCormick（CPT 专题）的对照表**：

| 训练目的 | CPT | SFT |
|---|---|---|
| **学习新的风格或体裁** | **✓（只有它能做）** | |
| 学习新知识 | ✓ | |
| **专精某一种风格/体裁** | ✓ | ✓ |
| 专精某种任务 | | ✓ |

> 原文："**CPT 用少量数据就足以让模型专精于某一种写作风格。**"

**中文资料（训练算法总结）在"适用性"一栏写得更狠**：

> 继续预训练"特别适用于**故事生成**或法律条文生成等强调语法和**语言风格**的场景"
> SFT **"不适用：任务目标模糊或依赖主观判断的场景（如小说创作、剧本生成）"**

**本项目做的是：拿 5 本书切成"骨架→正文"的指令对，做 SFT。**
也就是说 —— **一直在用错口的工具做这件事。** 这解释了为什么调了十几个版本，
"AI 味"始终压不干净、而且每修一项就冒出一项新的。

## 三、三条具体改进路线（按性价比排序）

### A. 换更小的基座 + 16-bit LoRA（**提高实验吞吐 2\~3 倍**）

现在每次训练要 **2.5\~19 小时**（7B 4-bit，还要背着量化的反量化开销）。
如果换成 **Qwen2.5-3B 或 1.5B + 16-bit LoRA**：

- 显存：3B LoRA(16bit) ≈ 8\~10GB；1.5B ≈ 5\~6GB → **都可能装得下**
- 速度：16-bit LoRA 比 QLoRA **快 2\~3 倍**（省掉每步的反量化）
- 而且资料明确：**风格/语气类任务只需要 rank 4\~8**（原文："Style / tone shift → r=4\~8, α=8\~16"）—— 本项目用的就是 rank 8 ✓ **说明容量不是瓶颈，7B 也是浪费**

**代价（必须说清）**：小模型的**语言能力**弱于 7B —— 可能句式更单调、长程一致性更差。
所以这不是"一定更好"，是"**值得实测**"——而且因为快 2\~3 倍，**试错成本低**。

### B. 加一个"继续预训练"阶段（**最可能治本**）

现在只做 SFT（2500 条指令对）。**从没做过 CPT**。

CPT 的做法：拿 5 本书的**原始文本**（约 1670 万字 ≈ 1100 万 token）跑 next-token 预测，
**更新全部层**，让模型先"泡"在卖报（网文作者"卖报小郎君"）的语言里，再上 SFT 教它按大纲写。

**文献给出的 CPT 配方（照抄即可）**：
1. **重热学习率再衰减**（基础模型停在余弦谷底，直接用极小学习率等于没训；要热回原峰值的约 10% 再衰减）
2. **混入个位数百分比的原分布文本**（防遗忘，这是这块最可靠的一招）
3. **CPT 之后必须补 SFT**（原文："CPT 会损伤指令跟随能力，因为原始文本里没有指令"）
4. 频繁存检查点、每个都测通用能力，找到"领域收益不再压过通用损失"的那个点

**本机成本**：1100 万 token × 6 × 70 亿参数 ≈ 4.2×10¹⁷ FLOPs
÷（4060 约 15 TFLOPS × 30% 利用率）≈ **26 小时/epoch**（用 LoRA 会更低）。**可行。**

**风险（必须说清）**：
- 文献建议 CPT 至少要有 **~100MB 领域文本**，本项目只有 **~50MB**（1670 万字）—— **处在临界以下**，
  收益可能不如预期
- 语料只有 5 本、且高度重复 → **有过拟合/背原文的风险**（已有查重工具盯着 ✓）
- 26 小时/epoch 在本机实际可能变成好几天（本机的降速问题还没根治）

### C. 换 LoRA 变体 / 换训练框架（**低成本小改**）

| 改法 | 预期 | 成本 |
|---|---|---|
| **DoRA**（权重分解 LoRA） | 同成本下质量更好，风格类任务收益明显 | LLaMA-Factory 支持 `use_dora: true`，改一行 |
| **rsLoRA / LoRA+** | 高 rank 下更稳 | 改配置 |
| **Unsloth** | 官方称 2 倍速、省 60% 显存 | 换训练框架，有迁移成本 |

## 四、一句话结论

| 问题 | 答案 |
|---|---|
| 现在的方法最好吗？ | **在 8GB + 7B 的前提下是被迫的合理选择（QLoRA），但"用 SFT 学文风"是错口的工具** |
| 有更好的吗？ | **有两条**：① 换小基座 + 16-bit LoRA（快 2\~3 倍，值得实测）；② **加 CPT 阶段**（最可能治本） |
| 能直接训练吗？ | **从零不可行**（差 3\~4 个数量级）；**CPT 可行**（26 小时/epoch）；**全参微调只能到 1.5B** |

**我定下的顺序**：**先做 A（快 2\~3 倍，让试错成本降下来）→ 再做 B（CPT）**。
理由：B 是本机最重的一次投入（几十小时），而在做它之前，
先把实验吞吐提上去，才能在 B 上少走弯路。

**不做的一件事**：不建议现在上全参微调。7B 差 8\~12 倍显存；换 1.5B 全参虽然塞得下，
但语言能力损失可能大过"更新全部权重"的收益 —— **这笔账没有实测支撑，不该赌。**
