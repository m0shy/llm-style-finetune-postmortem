# 微调塌缩诊断与修复方案

> 症状：Qwen2.5-7B-Instruct + 240 条微调后，输出复读、语法崩坏、逻辑断裂、直陈情绪——"不是人能写的语言"。
> 结论：**模型塌缩（degeneration collapse，模型只会复读训练集的退化现象）**，由"数据规模/多样性不足 + 指令单一 + 超参激进 + 解码无约束"四重叠加导致，非单一 bug。

---

## 一、证据（实测，非推测）

| 观察 | 数据 |
|---|---|
| instruction 种类 | **仅 2 种**，其中 228/240 用同一句 |
| output 段落长度 | 中位 **27 字**（一句一段） |
| output 句长 | 中位 **23 字**，"<10 字"占 **17%** |
| 数据集规模 | 240 条 ≈ **19.5 万字** |
| 指令硬约束 | 含"**多用短句**" |

模型输出症状：`湿漉漉的`×2、`轰！`×6、`几声闷响`复读、`那里的东西，仿佛在爆炸，爆炸的物品，仿佛在闷响`（主谓崩坏）、`心里越发焦急`（违反"不直陈情绪"）。

---

## 二、根因（按权重）

1. **指令单一**（最致命）：228/240 同一句 instruction → 模型把"指令串"与"输出网文腔"焊死；换指令即分布外崩溃。**这是首轮测试失败的直接原因。**
2. **数据分布本身促碎句**：段 27 字 / 句 23 字 + 指令明写"多用短句" → 模型学成"一句一段、句号碎片"。
3. **规模 vs 容量失衡**：19.5 万字不足以学会叙事组织，却足以覆盖基座语言能力 → 过拟合与遗忘同时发生。
4. **超参激进**：`lora_target: all` + `epoch 3` + `lr 1e-4`，在 240 条上全面加剧过拟合。
5. **样本全是中段片段**：无开头结尾、无完整事件弧 → 学不会收束，只会无限延伸。
6. **解码无约束**：无 `repetition_penalty` / `no_repeat_ngram_size` → 复读被放大。

---

## 三、先做 3 个 5 分钟自查（定权重，别盲改）

1. **解码复测**：同模型 + `repetition_penalty=1.3, no_repeat_ngram_size=4, temperature=0.8`。
2. **通用能力复测**：问"1+1 等于几，一句话"、"写 30 字请假微信" → 判断灾难性遗忘程度。
3. **任务内复测**：拿**训练集里真实 input 大纲**去测 → 若正常，说明是"指令迁移失败"，修复成本低。

---

## 四、修复（三层，按成本递增）

### Tier 1 · 立即止血（当天可做，不改数据）
- 用 `configs/sft/lingjing-sft-v2.yaml` 重训：`rank 8` / `target 收敛到 q,k,v,o,gate,up,down` / `epoch 2` / `lr 5e-5` / `dropout 0.1` / 加 eval 早停。
- 推理务必加：`temperature 0.8 · top_p 0.9 · top_k 40 · repetition_penalty 1.15~1.3 · no_repeat_ngram_size 4`。

### Tier 2 · 恢复语言能力 + 指令泛化（改数据）
- **指令多样化**：`scripts/diversify_instructions.py` 已产出 `dataset_lingjing_v2.jsonl`（240 条打散为 10 种等价指令，18–31 条/种；数据文件未随仓库发布），并**移除"多用短句"硬约束**，改为"长短句交错"。
- **混入 5–10% 通用中文语料**（alpaca 格式，500–2000 条）做 replay，防灾难性遗忘。
- 若 Tier 3 不做，则 Tier 2 是性价比最高的一步。

### Tier 3 · 真正"能写章节"（改范式）
- **改章节级样本**：1 条 = 整章大纲（100–200 字）+ 整章正文（3000–5000 字），需 300–500 章样本。
- **或改用编排层**（推荐，成本最低）：`scripts/outline_to_chapter.py`
  把章节大纲拆成 N 个场景 beat → 逐 beat 调用现有片段级模型 → 拼接 + 跨段去重 + 一致性收尾。
  **不需重训**，就能产出整章。

## 六、执行顺序建议

```
① 解码复测（5min）            → 确认复读占比
② 通用能力复测（5min）        → 确认遗忘程度
③ 任务内复测（5min）          → 确认是否只是指令迁移问题
④ 换 v2 yaml 重训（~1h）      → Tier 1
⑤ 若仍碎 → 用 v2 数据 + 通用语料重训（Tier 2）
⑥ 要整章 → 用 outline_to_chapter.py 编排（Tier 3）
```

**预期**：走到 ⑤ 后，模型应能"给大纲 → 产出连贯的 800 字片段"；整章靠 ⑥ 编排完成。
**诚实边界**：7B + 前沿数据量下的 SFT（指令微调），做不到"独立写完一本小说"；能做的是**受控的风格化扩写器 + 编排层**。
