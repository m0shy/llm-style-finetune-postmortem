# v16 验收结论：覆盖率历代最高，但风格被分段训练拖累（卖报＝网文作者"卖报小郎君"的简称）

> 训练：2522 条（过滤只作用续写 + 保护多人对白），rank 8，**分两段跑完 306 步**
> 第一段 150→230 用时 42 分钟（31.7 秒/步）；第二段 230→306 用时 71 分钟
> **train_loss 0.68**（v15 是 2.83）

---

## 一、结果：两个指标朝相反方向走

| 指标 | v8 | v13 | v15 | **v16** |
|---|---|---|---|---|
| **大纲要点覆盖率** | 3.8/6 (n=5) | 3.4/6 (n=5) | 2.7/6 (n=3) | **4.3/6 (n=3)** ⬆️ **历代最高** |
| **风格偏离项** | 未测 | 6 | **2** | **7** ⬇️ |
| 原文复读 | 0 | 0 | 0 | **0** ✓ |
| 破折号 | 0 | 0 | 0 | **0** ✓ |
| 异常符号 | — | 2/16 | 0/16 | **0/16** ✓ |

覆盖率单次采样最高到 5/6（两次），而且**六个要点里五个命中率 ≥2/3**。

## 二、风格退步的具体项（vs v15）

| 指标 | 卖报区间 | v15 | **v16** |
|---|---|---|---|
| 对白占比 | 13.2~35.6 | 22.4 内 | **10.1 偏低** |
| 平均句长 | 25.1~32.8 | 25.1 内 | **22.9 偏低** |
| 句长波动 | 14.9~20.8 | 15.4 内 | **12.6 偏低** |
| 段长波动 | 14.5~20.2 | 16.0 内 | **12.9 偏低** |
| 直陈情绪 | 0.19~1.3 | **0.9 内** | **1.64 偏高** |

同场景对比也证实：v16 的 B1 产出**对白占比只有 6.4%**（作者本人 41.1%），
几乎全是叙述 —— 而 v15 是 61.1%。

## 三、头号嫌疑：分段训练的副作用

`train_loss = 0.68`，而 v15 是 **2.83**。低到这个程度说明**每段都在过度下降**。

机制：分段时要把 `optimizer.pt`/`scheduler.pt` 改名（绕开 torch<2.6 的 CVE 限制），
所以**每段的优化器动量和 LR 曲线都从头开始** —— 每段开头都是最高学习率，
80 步内把 loss 猛压下去，模型被压向训练分布，风格反而走形。

**这是分段的固有代价，不是配置写错。**

## 四、🚨 一条方法论上的自我批评

**我同时改了两个变量**（数据 + 分段训练），所以这次的结果**没法干净归因**。
虽然分段是被迫的（不分段就是 195 秒/步），但我本可以先只改数据、用分段跑一次
作对照，或者先单独验证分段的影响。**这是我又一次违反了自己定的单变量原则。**

目前只能说"方向对得上"：数据改动 → 覆盖率涨；分段训练 → 风格掉。
**不能说"已证实"。**

## 五、v16 数据修正确实有效（这一条证据较硬）

- 大纲样本 348 → **396**（不再被情绪过滤器误削）
- 多人对白样本**保护了 343 条**（占续写 17%）
- 覆盖率 2.7 → **4.3**（+59%）

## 六、下一步（按优先级）

| 优先 | 动作 | 理由 |
|---|---|---|
| **P0** | **保留 v16 的数据，解决分段的副作用** | 覆盖率是我的核心诉求（1000字大纲→3000~4000字），不能丢 |
| **P0** | 分段时用 **`lr_scheduler_type: constant` + 较低学习率** | 没有余弦曲线就没有"重启即最高 LR"的问题，每段均匀 |
| **P1** | 或者：**升级 torch 到 ≥2.6** | 从根上解除 CVE 限制，就能保留 scheduler.pt、续训不再重置 LR。有搞坏环境的风险，需我拍板 |
| **P1** | 若不升级也不改调度：**只在机器凉的时候跑单段长训练** | 分段仅作崩溃兜底 |
| **P2** | 声线问题（C1 仍只有 1 个角色有对白） | 保护多人对白样本没起效，说明原因不在数据，可能在指令或容量 |
