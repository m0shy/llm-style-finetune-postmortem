# v6 评测结论 · 污染修好了，但还没到能用

> 评测时间：2026-09-12
> v6 = 3020 条样本 + **全样本注入专名块**（各源书自己的名字表），1 轮 367 步，eval_loss 2.8455
> 与 v5 用的是**同一套十探针、同一批生成参数**，可直接对比
> 串台＝训练污染（把 A 书人物写进 B 书）；文中「示例角色N / 示例设定」为发布时的打码占位符，代替真实的角色名与功法名。

## 一、总判断：**主要问题修好了，但还不够交付**

| 维度 | v5（无专名块） | v6（有专名块） | 结论 |
|---|---|---|---|
| **术语串台**（灵境/大奉专名泄漏） | 2 个探针命中 | **0** | ✅ **修好了** |
| **专名漂移**（同一人多个变体） | 6 个探针共 10 组 | **2 个探针共 2 组** | ✅ **大幅改善** |
| 破折号（我明令禁用） | 0 | **3 个探针各 1 处** | ❌ 新问题，已加后处理 |
| 大纲式（C1）用不用我的设定 | ❌ 拿灵境李东泽当主角 | ✅ **用了示例角色14、示例设定、堂主、干部** | ✅ 方向对了 |
| 感情戏·糖 | ❌ | 一般 | 略好于 v5，仍不如 v3 的结尾 |
| 感情戏·刀 | ❌ 完全没写出诀别 | 一般（有跑题） | 好于 v5，**仍不如 v3** |

**一句话**：v6 证明"注入专名块的机制"是有效的，但它解决的是**名字问题**，不解决**写作问题**。

## 三、但离"能用"还差三件事

### 1. 破折号（我明令禁用，v6 却出现了）

```
超凡职业——武夫          （插入语）
"轰隆——"               （拟声拉长）
他突然想起一个人来——那个叫柳婉儿的女人   （停顿）
```

**根因很清楚**：源书（卖报原著）大量使用 `——`，模型学了去。v5 因为欠训练没学会，v6 学会了。

**已修**（两层）：
- 生成端：`gen_chapter.py` 生成后自动走 `strip_dash()`
  （后接收尾引号或句末 → `……`；其余 → `：`）。实测：
  `超凡职业——武夫` → `超凡职业：武夫`；`"轰隆——"` → `"轰隆……"`；`想起一个人来——那个` → `……来：那个`
- 语料端：`build_multi_dataset.py` 对源文本做同样的规范化，**让下一轮不再学到这个习惯**

### 2. 错字与病句（v6 反而比 v5 多）

C1 里出现：
- `示例角色14**县**起锐利的目光`（应为"泛起"或"抬起"）
- `堂主**任**如疯狗`（多了一个"任"）

这两处是**字级崩坏**，不是风格问题，必须靠后处理或解读修掉。

### 3. 设定违背 + 爽点不落地（这条最要紧）

- **设定违背**：`两根示例设定从**他的手心**弹射而出`。
  我的设定里**示例设定自肩胛骨延伸**，这是男主第一个可见特例证据。模型写错了位置。
  说明"专名注入"只教会了它**名字**，没教会它**设定内容**（人物卡的一行摘要太短）。
- **爽点不落地**：大纲要求"掀桌 → 示例设定狂亮 → 示例设定横扫 → 瞬杀三名干部 → 一棘贯穿右臂 → 堂主下跪求饶"。
  v6 写出了"示例设定秒杀"，但**没有掀桌、没有示例设定、没有贯穿右臂、没有下跪求饶**。
  它写成了一个通用的打斗，而不是我那一章的爽点闭环。

## 四、感情戏人工判读

### G2（诀别前最后一顿饭）· v6

> 她知道时间不多了。这是她人生最后的一顿饭了。
> ……他一边吃着饭，一边看着厨房里的女人，她的动作很熟练……
> 李宗寒边吃边想，突然想起了一个人来：那个叫**柳婉儿**的女人，她是他的初恋……
> （此后约 15 行都在写这个初恋的往事）
> ……这是他人生中最后一次吃到女人亲手做的饭菜。

**优点**：开头"她知道时间不多了……让李慕寒吃个饱"直接立住前提；
"这女人平时不怎么做家务，可是到了做饭的时候，却好像很有经验似的"是好的细节。

**致命伤**：中段**大段跑题**去写初恋，把诀别的张力冲散了。这是典型的**详略失衡**，
正好踩在番茄档（番茄平台的风格档位）「关键情绪要放慢写细、无关信息一笔带过」的反面。

**对照 v3 的 G2**（仍是我读到的整晚最佳）：

> **他知道，这是她的告别。**
> **男人默默的吃着饭，他没说话，也没看女人的脸庞。**
> **床铺上留下了一个空荡荡的被窝，没有主人。**
> ……"我有一个朋友得了重病，可能撑不了多久了……"

v3 三句话就把刀递到读者手里，没有任何跑题。**这一段的水平到现在还没被超过。**

### G1（日常留白）· v6

亮点：`他们之间有很多话要聊，也有很多话不能说。但这些话都不重要。重要的只是此刻，他们安静地待在一起。`
这句是有留白质感的。

败笔：结尾又回到直陈（`这个男人，就是她的梦寐以求`），并且出现了 `温如霜/温颜霜` 的漂移，
排版里混进了大量不规则缩进。

## 六、该记住的

1. **"注入了名字"和"懂得了设定"是两件事**。v6 证明了前者可行，但示例设定射错位置说明后者还差得远。
2. **修一个问题会带出新问题**：v6 修掉串台，却因为学得更透而学会了源书的破折号。改动要有针对性回归。
3. **自动分再次不可信**：v6 十个探针自动判"通过"6 条，但人工读下来，C1 有错字+设定违背、G2 有跑题。
4. **指标本身也要校验**：这次的"破折号 x3"其实是我的脚本把 `——` 按两个字符计数造成的假象，
   实际每个探针只有 1 处。**连自己的度量都要抽查。**

## 七、补测：找到了「示例设定写错位置」的真凶（是我的 bug）

v6 评测里模型写出「两根示例设定从**他的手心**弹射而出」，而我的设定是**示例设定自肩胛骨延伸**。
我一度以为是模型不懂设定。回查我的人物卡原文（`02_人物/主角.md`，未随仓库发布）发现：

> 右眼觉醒后能看见规则连接线，**右肩胛骨下可生出示例设定**

**这条事实本来就在卡片里**，是摘要函数把它丢掉了，两个原因：

1. **跳过表格行**：这条事实写在 Markdown 表格里（`| 生理 | 桃痕自生者……右肩胛骨下可生出示例设定 |`），
   而 `_clean()` 里有一句 `if not s or s[0] in '#>-*|!': continue`，**把表格整行扔了**。
2. **只取开头 170 字**：卡片的开篇是氛围与灵感源流，硬设定其实在后半段。

**已修**（`outline_expand.py`）：摘要改为「身份段 + 所有命中能力关键词的行」，
关键词表含权柄/能力/形态/生理/肩胛/破穹/源理/禁忌等能力词，另含三处以「示例设定」占位的功法名。
修完后主角的摘要里已经能读到：

> ……右眼觉醒后能看见规则连接线，**右肩胛骨下可生出示例设定**……
> **觉醒独一档第五示例设定「示例设定」，自带真实破甲、超音速撕裂与神圣锋芒**

**教训**：把「模型不懂」当成结论之前，先确认「我到底有没有把信息给它」。
这次的错在我，不在模型。

## 八、补测结论：示例设定位置从「稳定写错」变成「2/3 写对」

**测试条件**（重启后 GPU 干净，三次采样）：
prompt 2067 字，注入 3 张卡片（主角 + 伏笔台账 + 跨循环传递清单），
**`含"肩胛"事实 = True`**（修好的摘要确实把"右肩胛骨下可生出示例设定"带进去了）。

| 采样 | 位置命中 | 判定 |
|---|---|---|
| 第 1 次 | 「他的**肩膀处**冒出了一道道尖锐刺目的白色光芒」 | ✅ |
| 第 2 次 | 「三道锐利的刀光从他的**掌心**生出」 | ❌ |
| 第 3 次 | 「示例设定再次从主角的**背后**延伸出来」「从**后背**刺入」 | ✅ |

**结论：2/3 写对**。修之前（v6 评测）是**稳定写"他的手心"**。

**顺带修好的一件事**：第一次测试（只注专名清单、不注卡片）时，模型写成了
「两名**法师**、一根**法杖**、装满**魔法卷轴**的背包」——**整个世界观跑偏成西幻**。
注入人物卡摘要之后，这个现象消失了，三次采样用的都是本作词汇（几处功法名以「示例设定」占位）。

**还差的 1/3**：写"掌心"说明**单靠 prompt 里给事实还不够稳定**。
下一步要么靠 v8 里补回的【逐条落实】约束强化，要么把这条事实提到更显眼的位置（如专名块里直接带注）。

### 两次测试方法上的教训（我自己的）

1. **第一次测试漏了人物卡摘要**，等于测的不是真实推理链路，"肩胛骨"事实压根没进 prompt。
   **测试必须走与被测对象一致的完整链路**，否则测出来的结论是假的。
2. **命中检查的关键词表漏了"掌心"**。我把 `手心/手掌` 列了进去，却漏了同义的 `掌心`，
   差点把它误判成"全部写对"。**停用词/关键词表要想到同义与近义表达。**
3. 复核时片段里混进了统计字典的文本（字典键正好是那些关键词），造成假命中。
   **统计输出与正文必须分开处理。**

### 查重的实测结论（好消息）

把 v6 的 8 个探针输出全部跑了一遍 `chapter_qa.py --dup`：

- **负例（v6 模型自写）**：8 个探针**全部零命中**，没有误报
- **正例（灵境原文摘录）**：准确命中

**结论：v6 的产出里没有任何源书原文复读。** 这一点在番茄的原创度要求上是过关的。

## 十、GPU 到了极限，本轮到此为止

连续高负载将近 8 小时后，GPU 出现**降级**：

| 测试 | 结果 |
|---|---|
| 简单矩阵乘 + `cuda.synchronize()` | ✅ 通过 |
| 加载 7B 模型做生成 | ❌ 连续三次崩（`device-side assert` / `illegal memory access`，分别发生在 LoRA `k_proj`、`_has_unfinished_sequences`、`logits_processor.scatter`） |

崩溃点分散在不同算子，属于**整体性不稳定**，不是某一处的代码 bug。
**建议：让机器冷却或重启，再跑下一轮。**

### 冷机恢复后的第一条命令（3 分钟，验证示例设定位置）

```bash
cd <项目目录>\LLaMA-Factory
PYTHONPATH= HF_HOME="<项目目录>\LLaMA-Factory\.hfcache" ^
<conda目录>\envs\<独立环境>\python.exe scripts\probe_one.py ^
    --adapter "<项目目录>\LLaMA-Factory\outputs\v6_multi" ^
    --ask "写一段两百字左右：主角被三名敌人围住，首次动用示例设定反击。要写清示例设定从哪里生出。" ^
    --n 3 --max-new 300
```

输出结尾会打印 `[命中统计]`，看 `肩胛/肩背/后背` 有没有命中、`手心/手掌` 有没有出现，
就知道加厚后的设定摘要到底治没治好这个错。
