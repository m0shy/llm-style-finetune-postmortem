# 专书写作模型 · 工具链使用说明（串台＝训练污染，把 A 书人物写进 B 书的正文）

> 目录：`<项目目录>\Datasets\scripts\`
> Python：`<conda目录>\envs\<独立环境>\python.exe`
> ⚠️ 跑任何加载模型的脚本前，先清空 `PYTHONPATH`（否则会被 <本地工具链> 的 shim 劫持，训练会崩）。
> ⚠️ 训练与生成**不能同时开**，8GB 显存一次只够一个。

---

## 一、按大纲生成一章（最常用）

```bash
cd <项目目录>\Datasets
PYTHONPATH= <conda目录>\envs\<独立环境>\python.exe scripts\gen_chapter.py ^
    --volume "第二卷" --chapter 3 ^
    --adapter "<项目目录>\LLaMA-Factory\outputs\v5_multi" ^
    --beats 3 --out ch02-03.md
```

- `--volume` 可只写"第一卷 / 第二卷 / 第三卷 / 第四卷"，会自动模糊匹配到具体分卷。
- `--beats N` 把本章大纲切成 N 段分别生成（段落越多，每段越细，也越慢）。
- `--dry-run` 只看将发给模型的 prompt，不加载模型，用来排查 prompt 问题。
- 先看某卷有哪些章：`--volume "第四卷" --list`（第四卷共 48 章）。

## 二、生成后做交付前质检

```bash
PYTHONPATH= <conda目录>\envs\<独立环境>\python.exe scripts\chapter_qa.py ch02-03.md
```

查出这几类问题：

| 检查项 | 说明 |
|---|---|
| **术语串台** | 正文里冒出《灵境行者》《大奉打更人》的专名（张元清 / 怀庆 / 天火宗 / 夜游神…） |
| **专名漂移** | 共享前两个字的多个变体并存（如 杨天宇 / 杨天佑 / 杨天禹） |
| **原文复读** | 与五本源书连续 14 字以上完全重合（需加 `--dup`，约 2 秒） |
| **归因违规** | 显灵 / 神迹 / 鬼神 / 因果轮回 等（平台合规红线：异常必须归因于机制） |
| 破折号 | 我的个人禁用项 |
| 古风词 / 八股词 / 半角标点 / 复读率 | 口径与手感检查 |
| 开篇 300 字冲突信号 | 番茄档（番茄平台的风格档位）要求 |
| 段长分布 | 看节奏是否"详略得当" |

**原文复读这一项为什么必须查**：模型是从这五本书训出来的，容易在某些段落直接"背原文"。
吐进我的书里既是抄袭风险，也踩平台的 AI 合规红线（要求原创度）。

```bash
# 带查重（较慢但值得）
PYTHONPATH= <conda目录>\envs\<独立环境>\python.exe scripts\chapter_qa.py 生成稿.md --dup
```

> **这个工具查不出"腔调同源""意象复用""描绘缺位""甜不甜疼不疼"。交付前必须人工通读。**

## 二之二、字级崩坏检测（查错字与字符混入）

```bash
PYTHONPATH= <conda目录>\envs\<独立环境>\python.exe scripts\typo_check.py 生成稿.md
PYTHONPATH= <conda目录>\envs\<独立环境>\python.exe scripts\typo_check.py 章节目录\
```

默认**只跑高精度信号**（实测在 16 个真实样本上**零误报**）：

| 信号 | 抓到过的真实案例 |
|---|---|
| **拉丁字母混入** | `怀Celel顿了一下`；还有更严重的 **`user` 混入正文**（chat 模板的角色标记泄漏，会让整章作废） |
| 繁体字混入简体正文 | `怀慶声音低沉` |
| 日文假名 / 韩文混入 | 模型偶尔会吐假名 |
| 同字连续 3 次以上 | 已排除拟声词（砰砰砰 属正常） |
| 半角标点混入 | `,` `;` `!` `?` 混进中文正文 |

另外有一个 `--deep` 深度模式，会额外跑两个**低精度**信号（人名变体、二字组合未见于源语料），
**误报很多**（实测 16 个样本出 109 处），只在我愿意人工筛的时候用。

### ⚠️ 诚实说明：错字这一类目前检测不了

`示例角色14县起`（应为泛起/抬起）、`堂主任如疯狗`（多一个"任"）、`示列角色4`（同音错字；「示例角色N」为发布时的打码占位符）
这三类**目前没有可靠的自动检测手段**。我试了两种办法，都不行：

1. **二字组合未见于源语料**：把五本源书切成 1300 万字的二字组合表，正常文本里
   "跨词边界"的组合（会山、意躺、色鞭）依然大量误报，一段 127 字的样本就出 9 条
2. **以人名首字开头但不属人名的三字串**：能抓到 `示列角色4`，但人名首字里有
   `上`、`人`、`寒`、`老` 这些常用字，16 个样本误报 109 处（`上生活`、`人生中`、`寒不由`）

**结论：没有语言模型的前提下，"这串字是不是人名/是不是错字"判不准。**
这一类只能靠人工通读，或者以后接一个专门的校对模型。

## 二之三、声线区分度检测（量「每人语气是否真的不一样」）

```bash
PYTHONPATH= <conda目录>\envs\<独立环境>\python.exe scripts\voice_check.py 产出目录\
PYTHONPATH= <conda目录>\envs\<独立环境>\python.exe scripts\voice_check.py 稿件.md --min-lines 3
```

**为什么需要**：我的验收要求之一是「能分辨出每一个人的语气都应该是怎么样的」，
这在之前**既没训练过**（样本硬约束只有人名）、**也没有验收手段**。

**做法**：抽对白 → 反推说话人 → 算每人声线特征（对白长度 / 短句率 / 语气词尾 / 问句率 / 感叹率）
→ 算 **组间方差 ÷ 组内波动**：≥2「听得出来是谁」，≥1「有点区分」，<1「千人一面」。

**⚠️ 归属实现的关键点**：要**取引号前最近出现的角色名**，不要用「人名+说话动词紧贴」的正则。
中文小说的实际写法经常是

```
主角冷笑一声，眼神阴森森的：
"我不认识你们！"
```

人名和引号隔了十几个字，紧贴式正则实测只认出 4 句对白，改成"最近人名"后能认出几十句。

**实测基准（供对照）**：

| | 灵境原著 | 模型产出（v11c） |
|---|---|---|
| 有声线的角色数 | **9** | **2** |
| 对白总数 | ~211 句 | 15 句 |
| 主角对白占比 | 40% | **80%** |

**结论：模型的问题不只是"语气不像"，而是"配角几乎没台词"** —— 15 句对白里 12 句是主角的。
没有台词，自然无从区分声线。**验收时要同时看"有台词角色数"和"主角占比"。**

**这个工具测不到什么**：只测可量化的层面（长短、语气词、句式），
测不出"这个人在不在乎"这类语义层的东西 —— 那必须人工读。

## 二之四、风格距离测量（把「像不像卖报」变成数字；卖报＝网文作者"卖报小郎君"的简称）

```bash
PYTHONPATH= <conda目录>\envs\<独立环境>\python.exe scripts\style_gap.py 产出目录\
```

用卖报原著（灵境 + 大奉）切 80 块 6000 字样本，算出 11 个指标的 **P10/P50/P90 区间**，
再看我的文本落在哪儿。**落在区间内 = 这个轴上看不出差别；落在区间外才值得关注。**

| 测的轴 | 意义 |
|---|---|
| 对白占比 | 卖报是对话驱动的 |
| 平均句长 / **句长波动** | 波动小 = 节奏平 |
| 平均段长 / **段长波动** | 波动小 = 详略均匀，没有张弛 |
| **直陈情绪词**（心里一暖/感到/意识到…） | 偏高 = 把情绪说出来，而不是用动作承载 |
| **套话连接词**（然而/于是/不由得…） | 偏高 = AI 腔 |
| 比喻词 / 升华句 | 偏高 = 滥用比喻、硬升华 |
| 用字丰富度 / 句首重复率 | 用字是否单调、句子开头是否雷同 |

**⚠️ 两条使用注意**（都是踩过的坑）：

1. **样本必须合并成一个长文本再测**。用字丰富度、句长波动这些都随文本长度变化，
   拿几百字的小样本跟 6000 字的基准块直接比，会得出"用字丰富度 52 vs 20"这种**纯长度造成的假象**。
   脚本已自动合并，并会在总字数 < 4000 时给出警告。
2. **对错判定要看区间，不要看单点**。稀有词（升华句之类）在短样本里方差极大，
   早期用"单条 vs 均值"比，连灵境原文都报出"偏离 322%"的假结论。

**已验证**：拿 5 份灵境原文当对照，11 项里 10 项落在区间内，工具可信。

## 二之五、同场景对比（最干净的风格对照）

```bash
PYTHONPATH= <conda目录>\envs\<独立环境>\python.exe scripts\compare_same_scene.py ^
    --probe-output 模型产出.txt ^
    --source "<old-lib>\《大奉打更人》\大奉打更人(501-955章).txt" ^
    --anchor "宋卿作为如今司天监的扛把子"
```

**为什么需要它**：`style_gap.py` 是拿产出和**整本原著的平均**比。这有混杂——我的探针（固定的对照测试输入）全是
高戏剧强度场景（掀桌/诀别/感情戏），而基准线是全书平均，**高戏剧场景天然比喻和情绪更多**，
比出来"AI 腔重"可能只是场景差异造成的假象。

这个工具换成**同一场戏、同一位置**：作者写到这里之后是怎么写的 vs 模型写到这里之后是怎么写的。
两段上下文完全一致，唯一差别是"谁写的"。

**实测价值**（2026-09-13）：同一场戏，卖报本人「直陈情绪 0.0 / 比喻词 0.0 每千字」，
模型「1.99 / 3.98」——把"AI 腔"从感觉变成了确凿的数字，而且自动标出该压哪几项。

**注意**：`--anchor` 要选探针输入里**独特**的一句话，工具靠它在源书里定位。

## 五、跑训练

**开跑前必做预检**（纯 CPU，几分钟，能防住 3 小时白跑）：

```bash
cd <项目目录>\Datasets
PYTHONPATH= HF_HUB_OFFLINE=1 <conda目录>\envs\<独立环境>\python.exe scripts\preflight_data.py --cutoff 2432
```

它会做三件事：
1. 结构检查：字段类型、instruction/output 是否为空
2. **metadata 类型一致性**：上次训练就是栽在 `metadata.chapter` 从数字变字符串，Arrow 直接抛错
3. 用 tokenizer 按 Qwen 模板实测每条样本的 token 数，报出**会被 cutoff 截断的条数**

实测记录（v8 数据集，3105 条）：

| cutoff | 被截断样本 |
|---|---|
| 2048 | **146 条**（多要点样本 85 条里有 46 条超限，大纲 396 条里有 100 条超限） |
| **2432** | **0 条** |

所以 v8 配置用 `cutoff_len: 2432`。**截断不是小事**：多要点样本的作用就是"把两个要点都写全"，
尾巴被截掉，这个训练目标本身就废了。

然后启动训练：

```bash
C:\Users\<user>\<本地工具链>\binaries\python\versions\3.13.12\python.exe ^
<项目目录>\LLaMA-Factory\scripts\v11_watchdog.py
```

看门狗（未随仓库发布）会自动处理"崩了从最近检查点续训"，最多 8 次。
配置文件：`configs\multi\qwen25-7b-multi-v8.yaml`（续训在同名配置加 `resume_from_checkpoint` 字段），数据集注册名 `multi_v8`。

### 踩过的坑：别用 `taskkill /F` 强杀训练

2026-09-11 夜里为了换数据集，用 `taskkill /F` 强杀了正在跑的 v5，随后重启的新进程在第 0 步直接炸：

```
RuntimeError: CUDA error: an illegal memory access was encountered
```

GPU 本身没问题（单独跑张量矩阵乘 + `cuda.synchronize()` 全通过），
**重新启动一次就正常了**，属于强杀导致的瞬时状态异常。

处理套路：
1. 先跑一次 GPU 冒烟测试确认硬件没坏（`torch.randn(...).cuda()` 做矩阵乘 + 同步）
2. 直接重启训练，不要急着改配置
3. 能不停就别停：优先等它跑完再换数据，而不是中途强杀

### 踩过的坑：4bit 长训练会偶发崩，必须挂看门狗

`CUDA error: an illegal memory access` 会在训练中途**随机**出现（8GB 笔记本显存 + 4bit QLoRA），
不是配置错。v2 时期是 `misaligned address`，同一类故障。跑一小时崩一次，无人值守扛不住。

**对策**：用自动续训看门狗，崩了就从最近检查点接着跑。

```bash
C:\Users\<user>\<本地工具链>\binaries\python\versions\3.13.12\python.exe <项目目录>\LLaMA-Factory\scripts\v5_watchdog.py
```

看门狗（未随仓库发布）会：有检查点就用 `*_resume.yaml`，没有就从头开始；每轮间隔 40 秒；最多重试 8 次；
并设 `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True` 缓解显存碎片。日志写在 `outputs\v5_watchdog.log`。

### 踩过的坑：续训被 torch.load 的 CVE 限制挡住

环境是 `torch 2.5.1+cu121` + `transformers 4.52.4`。直接续训会报：

```
ValueError: Due to a serious vulnerability issue in `torch.load` … we now require users
to upgrade torch to at least v2.6 … (CVE-2025-32434)
```

`transformers` 里的 `check_torch_load_is_safe()` 对 torch < 2.6 硬性抛错，**没有环境变量开关**。
续训要读 `optimizer.pt` / `scheduler.pt`，于是必崩。

**不要为此升级 torch**（会破坏现在能正常跑的环境）。正确解法是利用 `trainer.py` 的守卫逻辑：
它是「这两个文件**存在**才加载」，所以把检查点里的两个文件**改名保留**即可跳过整段加载：

```bash
cd <项目目录>\LLaMA-Factory\outputs\v5_multi\checkpoint-150
ren optimizer.pt optimizer.pt.bak
ren scheduler.pt scheduler.pt.bak
```

代价：AdamW 动量重置、LR 曲线有一处小跳变，可接受。
`rng_state.pth` 不走这个检查，**不要动**。

## 五之二、长训练用「分段训练」（治越跑越慢）

```bash
python scripts\chunked_train.py --conf-base configs\multi\qwen25-7b-multi-v16.yaml ^
    --out <项目目录>\LLaMA-Factory\outputs\v16_multi ^
    --target 306 --chunk 80
```

（`chunked_train.py` 未随仓库发布。）

**为什么必须分段**：实测规律 —— 同一个配置，**进程连续跑得越久，步时越退化**：

| 版本 | 连续跑 | 步时 |
|---|---|---|
| v15 | 2 小时 | 24.7 秒 |
| v13 | 3 小时 | 33 秒 |
| v11c | 5 小时 | 150 秒 |
| v16 | 8.7 小时 | **195 秒** |

已排除：散热（我实测 GPU <60℃）、浏览器抢显存（关掉 Edge 后没变）、时段。
真因是 **PyTorch 显存分配器只增不减**：专用显存顶格后数据走 PCIe 到共享显存。

**每 80 步重启一次进程，步时立刻从 190 秒回到 28 秒。**

**三个必须做对的点**（都踩过）：
1. 训练入口是 `llamafactory-cli.exe`，不是 `python train`
2. 临时配置路径要带 `configs/` 前缀
3. **每段都要把检查点的 `optimizer.pt` / `scheduler.pt` 改名** —— 否则 torch<2.6 的
   CVE 限制会让每段都崩。脚本里的 `unlock_resume()` 负责这一步。

代价：每段重置 AdamW 动量，LR 曲线有一处小跳变。

## 六、评测

评测分四层，各管一件事，别混着用：
